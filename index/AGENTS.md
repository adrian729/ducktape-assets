# Ducktape Assets for agents

Generated. Use these rules; do not edit this file by hand.

## Finding an asset

- Search `catalog.json` (one grep finds an asset and its URL). Ids are `<set>/<asset>`.
- Read `sets/<set>.json` only for what the catalog leaves out (hashes, bytes, components, parts).

## Using an asset

1. **Paste a URL.** Any HTML, CSS or Markdown references one file on jsDelivr, for example `https://cdn.jsdelivr.net/npm/@ranx729/ducktape-assets-walters-w102@1.2.0/webp/rabbit-church-bells-512.webp`. Only that file is transferred. `catalog.json` lists the exact URL of every width and format, so nothing has to be guessed.
2. **Pick and copy.** Keep a small `ducktape.json` listing the asset ids you want, with optional widths, formats and `masters: true`. `npx @ranx729/ducktape-assets copy` fetches exactly those files into the project (default `src/assets/ducktape/`), verifies every SHA-256 against the manifest, and writes `ducktape.manifest.json` beside them with dimensions, thumbhash, licence and attribution per asset. Re-running is idempotent.
3. **Resolve in code.** `npm i @ranx729/ducktape-assets` installs metadata and a resolver, zero images. `assets.image(id, { width })` returns `src`, `srcset`, `sizes`, width, height, thumbhash and licence. Bytes come from the CDN at request time, or from flow 2 when `base` points at the copied directory.

Prefer flow 2 for anything that must survive unattended: copied files do not depend on any host.

`ducktape.json`:

```json
{
  "pin": "@ranx729/ducktape-assets@3.4.0",
  "out": "src/assets/ducktape",
  "assets": [
    "walters-w102/rabbit-church-bells",
    { "id": "numbered-plate/stepped-ribbon", "formats": ["avif", "webp"], "max": 1024 },
    { "id": "illuminated-acanthus/divider-center", "masters": true }
  ]
}
```

## URLs

`https://cdn.jsdelivr.net/npm/@ranx729/ducktape-assets-<set>@<version>/<format>/<asset>-<w>.<ext>`

Exact-version URLs are immutable and cached for a year. Large sets are split into volume packages (`…-<set>-part2`); the catalog, the resolver and the copy command emit the right URL, so a consumer never notices the split.

## Rules

- Honour the licence block: show the `attribution` line when the asset's licence requires it.
- Never use `@latest` or range URLs; always an exact version from `index.json` or `catalog.json`.
- Never put a master on a page. Masters are for re-encoding in a build.
- Images are decorative by default (`alt=""`); use `description` when the image carries meaning.
- Always set the `width` and `height` attributes; the resolver returns them.
